02

项目背景

门店每天面对两类变化：顾客这一餐想吃什么，厨房今天还有多少食材。早期方案关注的，是菜单排序和促销依赖经验、加菜规律不易识别，以及高库存食材与晚间销量波动带来的损耗压力。

设计思路从现有 POS 与 ERP 经营数据出发，把库存、消耗、销量、损耗、调货和原料映射，与顾客偏好、人数、时段、客单价及加菜习惯结合，再连接到 Pad 菜单的推荐与促销。

本页呈现这一阶段的方案设计。后续存档记录显示项目范围曾重新讨论，因此这里保留的是早期机制与价值目标。

考虑用餐人数、时段、偏好、客单价与加菜习惯，设计 Pad 菜单的推荐顺序和组合。

03 /

晚间食材组合促销

晚间优先考虑高库存食材组合，探索加菜需求与库存消化之间的连接。

06

方案亮点

这套早期方案把顾客这一餐的需求与门店当天的库存放在一起考虑。POS、ERP 提供经营依据，Pad 菜单承接推荐动作；晚间组合则把食材周转纳入促销设计。

01

亮点一：围绕现有经营数据设计

方案以 POS 与 ERP 中的库存、消耗、销量、损耗、调货和原料映射为基础，先理解门店经营情况，再设计推荐机制。

02

亮点二：同一次推荐，兼顾用餐需求与库存

顾客偏好、人数、时段、客单价及加菜习惯共同进入推荐设计，同时考虑门店高库存食材，连接顾客需求与库存周转。

03

亮点三：把晚间促销与真实增量一起考虑

晚间优先推荐高库存食材组合，并将提高客单价、减少浪费、辨别新增消费作为价值目标。促销是否有效，需要后续用经营数据检验。

经营问题

菜单排序和促销依赖经验，顾客加菜规律不易识别。高库存食材与晚间销量波动，也给损耗和经营效率带来压力。

方案机制

方案围绕 POS 与 ERP 中的库存、消耗、销量、损耗、调货和原料映射数据，结合偏好、人数、时段、客单价与加菜习惯，设计 Pad 菜单的动态推荐与促销机制；晚间优先推荐高库存食材组合。

业务目标

提高客单价、减少食材浪费，并区分真正新增的消费与无效打折，为库存周转和毛利控制提供支持。
